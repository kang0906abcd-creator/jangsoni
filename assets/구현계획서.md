# 1. 프로젝트 개요

## 1.1 프로젝트 목적

기존 장기손해사정 지원 웹사이트 '장손이'를 현대적인 인터랙티브 웹사이트로 고도화한다.

웹사이트의 기존 업무 기능을 유지하면서 다음 요소를 강화한다.

1. 브랜드 캐릭터 '장손이'의 생동감 및 친근함
2. 스크롤 기반 정보 안내 경험
3. 장면 전환과 시각적 계층 구조
4. 전문 서비스에 적합한 정보 가독성
5. 사용자의 행동에 반응하는 자연스러운 캐릭터
6. 완성도 높은 반응형 웹 디자인

이 프로젝트는 생성형 AI와 바이브코딩을 통해 웹 디자인 및 인터랙션을 어느 수준까지 구현할 수 있는지 검증하는 실험적 목적을 포함한다.

## 1.2 핵심 콘셉트

**“장손이와 함께 차근차근 알아보는 손해사정”**

장손이는 복잡한 보험·법률·의학 자료를 안내하는 AI 파트너이다.

그러나 캐릭터의 성격은 전형적인 똑똑하고 빠른 AI 비서와 다르다.

장손이는 행동이 느릿하고, 조금 멍하며, 때로는 어리숙한 반응을 보이지만 언제나 성실하게 사용자를 안내한다.

핵심 대비는 다음과 같다.

- 시스템: 정확하고 신뢰할 수 있는 정보 제공
- 캐릭터: 순하고 느릿하며 조금 얼빠진 귀여움
- 디자인: 밝고 깔끔하며 현대적인 인터랙티브 웹
- 사용자 경험: 장손이와 함께 자료를 하나씩 살펴보는 느낌

**핵심 원칙: 귀여운 캐릭터가 신뢰할 수 있는 정보를 안내한다.**

## 1.3 참고 디자인

카카오 문화 페이지의 다음 경험을 참고한다.

- 큰 제목과 충분한 여백을 활용한 콘텐츠 배치
- 밝은 배경과 명확하게 구분되는 섹션
- 스크롤 진행에 맞춘 캐릭터 이동
- 캐릭터의 걸음과 스크롤 이동의 연결
- 캐릭터가 도착한 콘텐츠 카드의 포커스 변화
- 카드가 순차적으로 활성화되는 정보 전달
- 정적인 설명 페이지가 하나의 짧은 이야기처럼 진행되는 구성

참고 사이트의 춘식이 캐릭터나 브랜드 리소스를 사용하지 않는다.

**기존 장손이 캐릭터를 사용해 유사한 사용자 경험을 독립적으로 구현한다.**

정확한 내부 구현 방식이 공개되어 있지 않으므로, 스크롤 위치와 캐릭터 동작을 동기화하는 결과를 목표로 한다.

## 3.2 보존할 기존 기능

- 상품명, 가입일, 직업, 진단코드, 담보명, 쟁점 입력
- 입력값을 기반으로 한 관련 자료 자동검색
- 보험상품 약관 검색 및 담보 확인
- KCD 진단코드와 관련 지침 검색
- 법률 판례 검색
- PubMed 의학 논문 검색
- 금융감독원 분쟁조정정보 검색
- 계약 및 사건 타임라인 검토
- 카드뉴스 편집과 결과 반영
- 기존 화면 전환 및 입력값 처리

기능 내부의 분석 로직은 디자인 고도화 단계에서 임의로 변경하지 않는다.

## 3.3 기존 정보 구조 개선 제안

**이 항목은 기획자 협의 전까지 구현하지 않는다.**

현재 7개 주요 메뉴는 기능별로 나열되어 있다.

장기적으로 사용자의 업무 흐름에 따라 아래처럼 묶는 것을 검토할 수 있다.

| 업무 단계 | 관련 기능 |
|---|---|
| 사건 정리 | 타임라인 |
| 계약·의학적 근거 검토 | 약관, KCD, PubMed |
| 법적 근거 확인 | 판례, 금감원 분쟁조정 |
| 결과 작성 | 카드뉴스 |

현재 프로젝트에서는 기존 7개 기능을 그대로 유지하면서 시각적 배치와 안내 방법만 개선한다.

# 4. 장손이 캐릭터 디자인 규격

## 4.1 원본 캐릭터

기준 이미지는 기존 `index.html`에 포함된 투명 배경 PNG이다.

**기준 해상도: 864 × 934px**

반드시 유지할 외형 요소:

- 밝은 하늘색 털
- 복슬복슬하고 부드러운 3D 질감
- 둥근 얼굴과 크림색 주둥이
- 은색의 커다란 원형 안경
- 기존 눈, 코, 입의 형태와 비율
- 흰색·파란색 유니폼
- `AI CLAIM` 관련 의상 디자인
- 서류, 노란 클립보드, 돋보기
- 기존 장손이 브랜드 노트북
- 파란 꼬리
- 전체적인 귀여운 체형과 조명 스타일

새로운 캐릭터를 생성해서 원본을 대체하지 않는다.

원본과 무관한 다른 수달 이미지를 목업이나 개발 결과에 사용하지 않는다.

## 4.2 캐릭터의 정체성

**캐릭터 키워드**

순함 / 느릿함 / 멍함 / 소심함 / 어리숙한 귀여움 / 성실함 / 따뜻함

치이카와에서 느껴지는 것과 같은 순하고 작은 리액션, 소심함, 반 박자 느린 타이밍을 감성적 참고점으로 활용한다.

다만 치이카와의 외형, 구체적인 캐릭터 동작, 그림체를 복제하지 않는다.

장손이 고유의 성격을 만든다.

## 4.3 성격 정의

장손이는 사용자가 말을 걸지 않으면 자기 일을 하며 조용히 시간을 보낸다.

사용자가 다가오면 잠시 멍하니 있다가 뒤늦게 반응한다.

스크롤이 진행되면 부지런히 안내하려고 걸음을 옮기지만, 행동은 약간 굼뜨다.

장손이의 귀여움은 빠르고 과장된 움직임이 아니라 **작고 느린 행동과 어색한 타이밍**에서 만들어진다.

## 4.4 금지할 표현

- 빠르게 통통 튀는 동작
- 의미 없는 반복적인 상하 부유
- 마우스 포인터를 직접 쫓는 움직임
- 큰 몸통 회전이나 갑작스러운 점프
- 과장된 표정 변화
- 지나치게 사람 같은 움직임
- AI 생성 과정에서 얼굴이나 안경이 변형되는 것
- 발이 움직이지 않는데 캐릭터 전체가 미끄러지는 것
- 캐릭터가 실제 업무의 정확성을 떨어뜨리는 듯한 표현
- 사용자의 클릭이나 스크롤을 가로막는 인터랙션

# 5. 전체 디자인 시스템

## 5.1 스타일 방향

**Bright Minimal × Cute Character × Scroll Storytelling**

어두운 미래형 연구실, 홀로그램 UI, 네온 조명, 과도한 Glassmorphism은 사용하지 않는다.

캐릭터의 기존 3D 질감과 밝은 UI의 대비를 활용한다.

## 5.2 색상

| 용도 | 색상 | HEX |
|---|---|---|
| 기본 배경 | 순백색 | `#FFFFFF` |
| 보조 배경 | 오프화이트 | `#FBFCFE` |
| 연한 하늘색 | 연출 및 섹션 | `#E8F5FC` |
| 캐릭터 보조색 | 하늘색 | `#C5EAF8` |
| 브랜드 파란색 | 제목·강조 | `#2F6DB5` |
| 주요 행동 버튼 | 주황색 | `#FF7A29` |
| 본문 텍스트 | 진한 회색 | `#202830` |
| 보조 텍스트 | 회청색 | `#64748B` |
| 테두리 | 밝은 회색 | `#E8EBEF` |

주황색은 주요 버튼과 선택된 행동을 강조하는 데 제한적으로 사용한다.

카드의 기본 선택 강조는 브랜드 파란색을 사용한다.

## 5.3 타이포그래피

권장 서체: Pretendard 계열.

| 항목 | 데스크톱 | 모바일 |
|---|---|---|
| 메인 제목 | 52~64px | 32~38px |
| 섹션 제목 | 36~48px | 26~32px |
| 카드 제목 | 22~28px | 18~22px |
| 본문 | 16~18px | 15~16px |
| 보조 문구 | 13~14px | 12~14px |

- 한국어 줄바꿈을 고려한다.
- 중요한 텍스트는 이미지 안에 합성하지 않는다.
- 텍스트와 배경의 대비를 유지한다.
- 문단 길이를 짧게 구성한다.

## 5.4 레이아웃

- 데스크톱 기준: 1440 × 900px
- 콘텐츠 최대 너비: 1,200px
- 본문은 좌우 여백을 충분히 확보
- 카드 모서리: 20~28px
- 카드 내부 여백: 24~36px
- 섹션 간 배경색은 크게 차이나지 않도록 설계
- 캐릭터 뒤 원형·사각형 배경 요소 사용 금지
- 캐릭터가 콘텐츠를 가리지 않도록 전용 영역 확보

# 6. 전체 페이지 및 장면 설계

## Scene 01. Welcome ? 장손이의 첫인사

**기본 높이:** 약 100vh

### 레이아웃

- 전체 배경: 순백색
- 상단: 장손이 로고, 서비스 소개, 사건 분석 바로가기
- 좌측: 큰 환영 문구와 간단한 설명
- 우측: 기존 장손이 캐릭터
- 하단: 스크롤 유도 표시

### 예시 문구

“안녕하세요! 저는 장손이예요.”

“복잡한 손해사정, 함께 쉽고 빠르게 알아볼까요?”

### 캐릭터 배치

- 데스크톱 가로 약 380~440px
- 원본의 비율 유지
- 투명 배경 사용
- 주변에 원형 배경 없음
- 아래쪽에 부드러운 그림자
- 캐릭터의 기본 자세 유지

### 애니메이션

페이지 진입 시 장손이는 기본적으로 가만히 앉아 있다.

약간의 시간 후 눈을 천천히 깜빡인다.

사용자가 캐릭터를 향해 마우스를 가져가면 조금 늦게 고개를 들거나 반응한다.

사용자가 스크롤하면 다음 안내 장면으로 이어진다.

### 버튼

- `사건 분석 시작하기`: 하단 실제 사건 입력 폼으로 이동
- `둘러보기`: 소개 스크롤 섹션으로 이동

두 버튼 모두 별도 페이지 로딩 없이 동작한다.

## Scene 02. 장손이 소개

**권장 높이:** 약 120vh

### 목적

장손이가 어떤 역할을 하는 캐릭터인지 소개한다.

### 핵심 문구

“필요한 자료를 하나씩 찾아드릴게요.”

### 콘텐츠

- 보험상품 약관 확인
- 진단 및 의학 자료 검색
- 판례와 분쟁조정자료 검토

### 연출

- 캐릭터는 화면 오른쪽에 남음
- 스크롤 진행에 따라 캐릭터 크기 축소
- 설명 문장은 차례대로 등장
- 현재 소개하는 내용에 맞춰 작은 시선 변화
- 큰 이동보다는 제자리에서 느린 리액션

### 캐릭터 동작

기본 `idle_blank`.

문구가 등장할 때 잠깐 바라본다.

필요한 경우 `idle_think` 상태로 전환한다.

### 시각적 연출

정보 칩 또는 문서 카드가 순차적으로 나타난다.

장손이는 서류를 바라보며 생각하는 표정을 짓는다.

현재 입력 화면의 항목을 그대로 설명하되, 실제 입력 구조를 임의로 변경하지 않는다.

### 캐릭터 동작

`idle_think` 중심.

- 서류를 바라봄
- 눈을 느리게 깜빡임
- 잠깐 멍하게 정지
- 정면을 다시 바라봄

## Scene 04. Scroll Walk Journey ? 핵심 인터랙션

**이 장면이 이번 프로젝트의 가장 중요한 디자인 요소이다.**

**참고:** 사용자가 제공한 카카오 문화 페이지의 춘식이 스크롤 이미지 3장.

### 핵심 목표

장손이가 스크롤을 따라 아래로 걸어가면서 기능 카드들을 순서대로 안내한다.

장손이의 이동 위치에 맞춰 해당 카드가 활성화된다.

사용자가 아래로 스크롤하면 다음 카드가 활성화되고, 위로 돌아가면 이전 카드가 다시 활성화된다.

### 기본 구조

데스크톱:

- 왼쪽 30~35%: 장손이 이동 영역
- 오른쪽 60~65%: 정보 카드
- 두 영역 사이에 충분한 여백
- 캐릭터의 위치와 카드의 위치를 스크롤로 연결

캐릭터는 실제 페이지 안에 존재하는 경로를 따라 이동하는 것처럼 표현한다.

스크롤 시 발의 걸음 동작이 나타나야 하며, 걷는 동안 캐릭터가 단순히 미끄러지지 않아야 한다.

### 안내할 카드

기존 기능을 유지하며 다음 일곱 가지를 순서대로 소개하는 시안을 사용한다.

| 순서 | 카드 | 설명 |
|---|---|---|
| 1 | 사건 타임라인 | 날짜·이력과 검토 항목 |
| 2 | 보험 약관 | 지급사유와 제한사유 |
| 3 | KCD 진단코드 | 진단코드와 분류 정보 |
| 4 | 판례 검색 | 관련 법률 판례 |
| 5 | 의학 논문 | PubMed 자료 |
| 6 | 금감원 분쟁조정 | 분쟁조정사례와 결정례 |
| 7 | 카드뉴스 제작 | 결과물 작성 및 편집 |

이 순서는 기존 메뉴 구조와 별도로 **소개 페이지용 시각적 배열**이며, 실제 메뉴 재분류나 통합을 의미하지 않는다.

### 카드 포커스 동작

사용자가 스크롤하면 다음 연출을 수행한다.

**대기 카드**

- 기본 배경 흰색
- 연한 회색 테두리
- 약간 축소된 크기
- 절제된 그림자
- 제목과 내용은 읽을 수 있는 상태로 유지

**활성화 카드**

- 크기 100%로 복귀
- 브랜드 파란색 테두리 또는 포인트 라인
- 그림자 강화
- 아이콘 및 설명 등장
- 제목의 시각적 강조
- 필요하면 상세 설명 표시

**지난 카드**

- 강조 스타일 해제
- 기존 크기로 자연스럽게 축소
- 정보는 그대로 유지
- 스크롤을 다시 올리면 재활성화

### 카드 모션 수치

- 기본 카드 배율: 0.97
- 활성 카드 배율: 1.00
- 활성화 전환: 450~650ms
- 카드 이동 거리: 12~20px 이내
- Easing: 부드러운 `power2.out` 계열
- 화면 내 활성 카드: 기본적으로 하나

실제 문서 요소의 높이와 접근성을 고려하여 수치는 조정 가능하다.

### 스크롤에 따른 장손이 이동

카드 1에서 카드 2로 넘어가면 장손이가 카드 2 방향으로 느릿하게 걸어간다.

걸음 도중에는 작은 몸통 움직임과 발동작이 발생한다.

다음 카드 근처에 도착하면 잠깐 멈추고 카드를 바라본다.

이후 Idle로 복귀한다.

### 장손이 이동의 성격

- 빠르게 뛰어다니지 않음
- 약간 굼뜨게 걷기
- 몸통의 상하 흔들림은 미세하게
- 발동작과 실제 위치 이동이 일치
- 사용자가 스크롤을 멈추면 잠시 후 걷기를 멈춤
- 다음 카드에 도착하면 아주 짧게 멍하니 서 있음
- 뒤늦게 고개를 돌려 현재 카드를 확인

### 중요한 UX 규칙

**카드의 포커스는 즉시 바뀌고, 장손이의 감정 반응만 반 박자 늦는다.**

캐릭터성을 위해 정보 탐색 자체를 지연시키지 않는다.

사용자가 스크롤을 매우 빠르게 내리면 장손이가 모든 걸음을 억지로 재생하지 않고 최종 위치로 자연스럽게 이동한다.

스크롤을 위로 올렸을 때에도 동일한 기준으로 카드와 캐릭터 위치를 복원한다.

### 이동 경로

- 세로 방향을 기본으로 사용
- 카드의 중앙 높이를 이동 기준점으로 사용
- 필요하다면 완만한 곡선을 적용
- 과도한 지그재그 이동 금지
- 이동 경로 자체를 시각적으로 노출할 필요 없음
- 실제 스크롤 거리와 캐릭터 위치를 동기화

### 예상 섹션 높이

7개 카드 기준으로 약 400~550vh를 초기 시안으로 제안한다.

실제 카드 크기, 텍스트 길이, 스크롤 체감 속도에 따라 조정한다.

# 7. 2.5D 캐릭터 제작 설계

## 7.1 기술적 전제

기존 장손이 이미지는 투명 배경 PNG 한 장이다.

이 이미지를 통째로 이동시키는 것만으로는 자연스러운 보행이나 눈 깜빡임을 구현할 수 없다.

따라서 캐릭터를 움직일 수 있는 부분별 이미지로 분리하거나, 보행 장면용 프레임을 새롭게 제작해야 한다.

## 7.2 권장 방식

**원본 PNG + 2.5D 부분 리깅 + 보행 스프라이트**

기본 대기와 표정은 부분 리깅으로 구현한다.

걸음 동작은 여러 프레임의 스프라이트로 구현한다.

기존 캐릭터 외형을 최대한 보존하면서 필요한 움직임만 추가하는 방식이다.

## 7.3 필요한 레이어

| 레이어 | 역할 |
|---|---|
| Body | 몸통 및 기본 자세 |
| Head | 고개 움직임 |
| Eyes Open | 평상시 눈 |
| Eyes Closed | 눈 깜빡임 |
| Glasses | 안경 위치 유지 |
| Left Arm | 왼팔 움직임 |
| Right Arm | 오른팔 움직임 |
| Left Leg | 왼발 보행 |
| Right Leg | 오른발 보행 |
| Tail | 꼬리 움직임 |
| Props | 서류·클립보드·돋보기 |
| Laptop | 노트북 |
| Shadow | 바닥 그림자 |

실제 레이어 분리 과정에서는 머리나 팔에 가려져 원본에 없는 부위를 복원해야 할 수 있다.

복원한 부위는 기존 장손이의 체형, 털 색, 질감과 일치해야 한다.

## 7.4 걷기용 캐릭터 제작

현재 원본은 앉은 상태이며 서류와 돋보기를 들고 있다.

따라서 자연스러운 보행을 구현하려면 **걷는 자세의 장손이**를 추가로 제작해야 한다.

이 과정에서 새로운 수달을 생성해서는 안 된다.

원본 캐릭터의 외형과 복장, 얼굴을 기준으로 걷는 포즈를 파생시킨다.

### 필수 보행 프레임

초기 목표:

- Stand
- Walk Contact Left
- Walk Passing Left
- Walk Contact Right
- Walk Passing Right
- Settle / Stop

권장 보행 주기: 6~8프레임.

권장 재생 속도: 약 8~12fps에서 시작해 실제 결과에 맞춰 조정.

### 원본 소품 처리

원본 캐릭터에는 노트북, 서류, 돋보기 등이 포함되어 있다.

걷는 캐릭터에서도 소품이 갑자기 사라지거나 다른 물건으로 변하지 않아야 한다.

초기 제안:

1. Welcome 장면에서는 원본의 앉은 자세를 그대로 사용한다.
2. 보행 구간 진입 시 앉은 자세에서 서 있는 자세로 전환한다.
3. 노트북은 원래 위치에 남는 배경 소품으로 처리하거나 장면 전환 중 자연스럽게 화면 밖으로 이동시킨다.
4. 서류와 돋보기는 걷기용 포즈에 맞춰 안정적으로 유지하거나, 별도의 소품 내려놓기 연출을 만든다.

정확히 어떤 소품을 들고 걸을지는 첫 보행 시안에서 검증하고 확정한다.

소품이 부자연스럽게 사라지는 연출은 허용하지 않는다.

## 7.5 좌우 방향

캐릭터가 걸어가는 방향에 따라 필요한 경우 별도 방향 이미지를 제작한다.

**전체 이미지를 단순히 좌우 반전하지 않는다.**

유니폼과 노트북에 글자가 포함되어 있어 좌우 반전을 적용하면 글자가 뒤집힐 수 있기 때문이다.

초기에는 정면에서 약간 측면을 바라보는 걷기 동작 하나를 중심으로 구현한다.

## 7.6 원본 일관성 검수

각 보행 프레임을 원본과 비교한다.

- 얼굴 형태
- 안경 크기
- 털 색상
- 눈 크기
- 코와 입 위치
- 의상 구조
- 브랜드 로고
- 전체 비율
- 질감과 조명

원본의 특징이 눈에 띄게 달라진 프레임은 사용하지 않는다.

# 8. 장손이 행동 상태 머신

## 8.1 상태 정의

| 상태 ID | 설명 |
|---|---|
| `idle_blank` | 멍하니 있는 기본 상태 |
| `idle_think` | 서류를 확인하는 상태 |
| `notice_user` | 사용자를 뒤늦게 인지 |
| `gentle_greet` | 작은 인사 |
| `walk` | 스크롤에 맞춰 걷기 |
| `walk_stop` | 이동 후 느릿하게 멈추기 |
| `explain_soft` | 정보 카드 바라보기 |
| `analysis_wait` | 실제 데이터 검색 중 |
| `analysis_done` | 검색 완료 후 작은 반응 |

## 8.2 기본 대기 상태

**Idle Blank**

- 평소에는 대부분 움직이지 않음
- 약 4~7초 간격으로 눈 깜빡임
- 가끔 8~12초 간격으로 서류를 흘끗 봄
- 상체 호흡은 매우 미세하게
- 일정한 반복 주기를 피함
- 기본적인 온화한 미소 유지

눈 깜빡임:

- 지속 시간 약 150~250ms
- 상황에 따라 느린 눈 깜빡임 사용
- 지나치게 자주 깜빡이지 않음

## 8.3 Hover 반응

**Notice User**

사용자가 캐릭터에 마우스를 올릴 경우:

1. 약 350~650ms 정도 반응 지연
2. 캐릭터가 시선을 약간 올림
3. 눈을 한 번 깜빡임
4. 고개를 2~4도 기울임
5. 약간 멍하게 바라봄
6. 원래 자세로 복귀

Hover가 잠깐 발생했다가 사라지면 반응을 생략할 수 있다.

Hover 이벤트가 발생할 때마다 처음부터 다시 실행하지 않는다.

## 8.4 클릭 반응

**Gentle Greet**

1. 클릭 입력을 즉시 정상 처리
2. 캐릭터 반응은 약 100~200ms 뒤 시작
3. 작은 눈 깜빡임
4. 고개 숙임 또는 작은 끄덕임
5. 원래 자세로 천천히 복귀

큰 손짓, 점프, 과도한 바운스 금지.

## 8.5 걸음 동작

**Walk**

사용자의 스크롤 방향과 이동량에 따라 재생한다.

- 스크롤이 진행되면 걷기 시작
- 보폭은 짧고 느릿하게
- 몸통은 아주 조금 흔들림
- 발동작과 이동 방향이 일치
- 급격한 위치 점프 최소화
- 스크롤을 멈추면 자연스럽게 정지
- 멈춘 후 작은 지연을 두고 정면 또는 카드를 바라봄

캐릭터가 화면상 멈춰 있는데 발만 계속 움직이는 현상을 방지한다.

## 8.6 카드 안내

**Explain Soft**

활성화된 카드 근처에 도착하면:

1. 잠깐 멍하니 멈춤
2. 카드를 바라봄
3. 작은 고개 움직임
4. 정면을 바라봄
5. 다음 스크롤을 기다림

## 8.7 분석 대기

**Analysis Wait**

- 서류 또는 돋보기 확인
- 느린 눈 깜빡임
- 작은 고개 움직임

실제 검색이 끝나지 않았는데 완료된 것처럼 행동하지 않는다.

## 8.8 행동 우선순위

권장 상태 우선순위:

1. 실제 업무 처리 상태
2. 사용자 클릭
3. 스크롤 이동
4. Hover
5. 기본 Idle

단, 스크롤로 카드가 바뀌는 정보 전달 UI는 캐릭터의 현재 감정 애니메이션과 무관하게 즉시 업데이트한다.

# 9. 스크롤 인터랙션 상세 명세

## 9.1 스크롤과 캐릭터 상태의 관계

스크롤은 두 가지 요소를 제어한다.

**A. 공간적 움직임**

- 캐릭터 위치
- 이동 경로
- 크기
- 카드와의 상대 위치

**B. 행동 상태**

- 걷기
- 정지
- 카드 바라보기
- 고개 끄덕임
- 기본 자세 복귀

위치 이동은 연속적으로 처리하고 감정 표현은 별도의 상태 전환으로 처리한다.

## 9.2 활성 카드 계산

각 카드는 `data-step` 속성을 가진다.

스크롤에 따라 현재 화면의 기준 위치에 가장 가까운 카드를 활성화한다.

초기 기준점은 뷰포트 높이의 약 55% 위치로 설정한다.

카드가 이 기준점을 통과할 때 활성 상태를 변경한다.

카드 경계에서 활성 상태가 빠르게 반복 전환되지 않도록 작은 히스테리시스 구간을 둔다.

## 9.3 장손이 위치 계산

각 카드 근처에 캐릭터가 도착해야 할 기준 좌표를 설정한다.

스크롤 진행률을 0~1로 정규화한 다음 각 기준점 사이의 위치를 보간한다.

캐릭터는 화면에 고정된 한 점에만 머무르는 것이 아니라, 스크롤에 따라 해당 카드와 연결되는 위치를 따라 이동한다.

## 9.4 카드 포커스 규칙

`activeStep`을 단일 상태값으로 유지한다.

현재 단계와 일치하는 카드에 `is-active` 클래스를 적용한다.

이전 카드와 다음 카드에는 별도의 비활성 스타일을 적용한다.

활성 카드가 변경되면 다음을 동기화한다.

- 카드의 강조 상태
- 진행 표시
- 캐릭터 목표 위치
- 캐릭터 안내 동작
- 필요한 설명 텍스트

## 9.5 빠른 스크롤

사용자가 여러 카드를 한 번에 건너뛰면 중간 보행 애니메이션을 모두 재생하지 않는다.

최종 활성 카드와 목표 위치를 우선 반영한다.

캐릭터는 짧고 자연스러운 위치 보정 후 정지 상태로 전환한다.

사용자의 스크롤 속도를 캐릭터가 따라가지 못해 콘텐츠와 캐릭터가 영구적으로 분리되는 현상을 방지한다.

## 9.6 역방향 스크롤

스크롤을 위로 올리면:

- 이전 카드 활성화
- 이전 위치로 이동
- 보행 동작 재개
- 도착 후 정지

좌우 반전으로 브랜드 텍스트가 뒤집히지 않도록 주의한다.

## 9.7 화면 전환

소개 구간 종료 시 캐릭터는 자연스럽게 업무 화면용 작은 안내 도우미로 축소되거나 화면에서 퇴장한다.

소개 페이지의 스크롤 좌표와 업무 화면의 스크롤 좌표는 독립적으로 관리한다.

# 10. 그림자 및 공간감 처리

## 10.1 핵심 원칙

그림자는 캐릭터의 실제 움직임과 일치해야 한다.

장손이 전체 PNG를 위아래 이동시키면서 기존에 포함된 그림자까지 같이 이동시키는 방식은 사용하지 않는다.

## 10.2 Welcome 장면

기존 원본의 접지 그림자와 노트북 그림자를 활용할 수 있다.

캐릭터의 눈이나 고개만 움직이는 경우 바닥 그림자는 거의 변하지 않아도 자연스럽다.

추가 CSS 그림자를 적용할 때는 기존 그림자와 겹쳐 이중 그림자가 발생하지 않도록 한다.

## 10.3 걷기 장면

걷기용 캐릭터에서는 필요에 따라 원본 그림자를 분리한다.

바닥 접지 그림자를 별도 레이어로 관리한다.

- 발이 지면에 닿는 순간 그림자 강조
- 발을 들어올릴 때 자연스러운 형태 변화
- 그림자는 발 아래에 유지
- 몸통 이동과 보행 주기를 연동
- 과도한 그림자 확대·축소 금지

## 10.4 그림자 스타일

- 짙은 검정색 사용 금지
- 회청색의 낮은 불투명도
- 부드러운 Blur
- 지면에 자연스럽게 닿는 느낌
- 강한 게임 캐릭터 그림자 표현 금지

## 10.5 영상 방식으로 확장할 경우

향후 생성형 AI 영상을 도입한다면 캐릭터와 그림자의 동시 움직임을 포함해 생성할 수 있다.

단, 투명 배경 위를 이동할 경우에는 영상 내부 그림자와 CSS 그림자의 중복 여부를 검토해야 한다.

최초 구현에서는 실시간 3D 물리 기반 그림자 계산을 요구하지 않는다.

# 11. 구현 기술 및 아키텍처

## 11.1 1차 기술 구성

| 기술 | 용도 |
|---|---|
| HTML5 | 기존 웹사이트 구조 |
| CSS | 레이아웃, 색상, 카드 스타일 |
| JavaScript | 상태 관리 및 UI 이벤트 |
| GSAP | 모션과 전환 |
| GSAP ScrollTrigger | 스크롤 진행률 및 장면 제어 |
| GSAP MotionPathPlugin | 필요시 이동 경로 제어 |
| 2.5D 이미지 레이어 | 눈, 고개, 팔 등의 부분 움직임 |
| 스프라이트 애니메이션 | 보행 동작 |
| 이미지 편집 및 AI 보조 | 원본 파츠 분리, 빠진 부분 복원 |

Three.js나 실시간 3D 모델은 첫 번째 구현의 필수 기술이 아니다.

## 11.2 파일 구조

초기 권장 구조:

- `index.html` ? 기존 HTML 및 화면 연결
- `assets/mascot/original.png` ? 원본 캐릭터
- `assets/mascot/rig/` ? 부분 애니메이션용 이미지
- `assets/mascot/sprites/` ? 걷기 동작 프레임
- `assets/mascot/shadows/` ? 그림자 리소스
- `css/tokens.css` ? 컬러·타이포그래피 변수
- `css/landing.css` ? 스크롤 소개 페이지
- `css/mascot.css` ? 캐릭터 스타일
- `js/mascot-controller.js` ? 캐릭터 상태 머신
- `js/scroll-journey.js` ? 스크롤 및 카드 동기화
- `js/screen-bridge.js` ? 기존 화면 연결

파일을 분리하더라도 기존 HTML의 기능 ID와 이벤트 동작을 유지한다.

## 11.3 기존 코드와 연결

기존의 다음 요소를 보존한다.

- `#intro`
- `#menu`
- `#start`
- `#intro-yak`
- 기존 `in-*` 입력 요소
- `data-go` 이동 로직
- `showScreen()`
- `runAutoSearch()`

소개 섹션은 기존 `#intro` 내부에 추가하거나, 동등한 화면 연결 구조로 구성한다.

기존 `#intro`에 적용된 전체 화면 중앙 정렬 스타일은 새 스크롤 구조에 맞게 수정해야 한다.

이때 입력 필드 ID, 조회 로직, 이벤트 리스너가 손상되지 않도록 한다.

## 11.4 상태 관리

캐릭터 상태와 카드 상태를 분리한다.

예상 상태값:

- `mascotState`
- `activeStep`
- `scrollProgress`
- `scrollDirection`
- `isWalking`
- `isInteracting`
- `reducedMotion`
- `isWorkspaceMode`

한 이벤트가 서로 다른 캐릭터 동작을 중복 실행하지 않도록 상태 전환을 통제한다.

# 12. 반응형 및 접근성

## 12.1 데스크톱

- 캐릭터와 카드의 2열 구성
- 스크롤 연동 보행 활성화
- 카드 포커스 애니메이션 활성화
- 마우스 Hover 반응
- 캐릭터의 이동 영역 충분히 확보

## 12.2 태블릿

- 캐릭터 크기 축소
- 카드 폭 확대
- 이동 경로 단순화
- 콘텐츠와 캐릭터 겹침 방지

## 12.3 모바일

- 캐릭터 크기 약 120~160px에서 검토
- 콘텐츠를 가리지 않는 위치에 배치
- 마우스 Hover 대신 터치 반응
- 이동 경로를 세로 중심으로 단순화
- 화면 키보드가 나타나면 캐릭터 고정 해제 또는 숨김
- 긴 문장과 카드가 화면 밖으로 밀리지 않도록 처리

모바일에서 데스크톱과 동일한 모든 애니메이션을 유지할 필요는 없다.

## 12.4 모션 감소 설정

사용자가 모션 감소 설정을 활성화한 경우:

- 자동 보행 비활성화
- 과도한 화면 이동 제거
- 캐릭터는 정적인 이미지 또는 최소한의 변화만 사용
- 카드 포커스는 애니메이션 없이 적용
- 모든 기능은 정상 동작

## 12.5 접근성

- 키보드만으로 전체 기능 접근 가능
- 스크롤 애니메이션 때문에 콘텐츠 접근이 제한되지 않음
- 장식용 캐릭터는 화면 읽기 프로그램의 중복 설명을 유발하지 않음
- 카드 선택 상태는 색상 외 방법으로도 구분
- 주요 버튼의 포커스 표시 유지
- 과도한 깜빡임과 섬광 효과 사용 금지

# 13. 장손이 대사 및 마이크로카피

## 13.1 말투

장손이는 따뜻하고 조심스러운 말투를 사용한다.

너무 장황하게 설명하지 않는다.

사용자에게 부담을 주는 과장된 감탄사를 피한다.

## 13.2 안내 문구 예시

**첫인사**

“안녕하세요! 저는 장손이예요.”

**기능 소개**

“필요한 자료를 같이 찾아볼까요?”

**자료 안내**

“이쪽에도 한번 살펴볼 게 있어요.”

**사건 입력**

“사건 정보를 알려주시면 제가 찾아볼게요.”

**검색 대기**

“음… 자료를 살펴보고 있어요.”

**검색 완료**

“찾아본 자료를 모아봤어요!”

**다음 섹션**

“그럼 다음으로 가볼까요?”

## 13.3 말투 제한

캐릭터는 느리고 조금 어리숙하지만, 실제 업무 결과의 신뢰성까지 가볍게 표현하지 않는다.

보험금 지급 여부, 의료적 판단, 법적 결론에는 정확하고 중립적인 시스템 문구를 사용한다.

캐릭터의 장난스러운 대사는 실제 판정과 구분된 안내 영역에서만 사용한다.

- 분석 결과가 규칙 기반인지 AI 기반인지의 명확한 표현

# 15. 성능 및 품질 기준

## 15.1 애니메이션 성능

- 데스크톱에서는 부드러운 60fps를 목표로 최적화
- 모바일에서는 기기 성능에 따라 애니메이션 단순화
- 화면 이동은 가능한 한 `transform`과 `opacity` 사용
- 스크롤마다 복잡한 DOM 재계산 최소화
- 이미지 크기와 렌더링 비용 최적화

## 15.2 로딩 전략

- 원본 장손이 PNG를 우선 표시
- 필요한 애니메이션 리소스만 초기 로딩
- 이후 보행 프레임을 순차적으로 불러오기
- 리소스 로딩에 실패하면 원본 PNG 표시
- 애니메이션 실패가 기존 업무 기능을 막지 않도록 처리

## 15.3 품질 확인

다음 문제는 수정 대상으로 판단한다.

- 원본과 다른 캐릭터처럼 보이는 프레임
- 눈이나 안경의 위치 어긋남
- 보행 중 발 미끄러짐
- 카드 포커스와 캐릭터 위치 불일치
- 캐릭터의 갑작스러운 위치 이동
- 그림자의 부자연스러운 이동
- 스크롤을 멈췄는데 걷기가 계속됨
- 카드 선택이 반복적으로 깜빡임
- 모바일에서 캐릭터가 내용을 가림
- 기존 메뉴 기능 오류
- 과도한 애니메이션으로 인한 성능 저하

# 16. 단계별 개발 로드맵

## Phase 0 ? 기존 목업 기능 검증

목표: 리디자인 전 기능 보존 기준 확보.

- 기존 화면 목록 정리
- 입력값과 자동검색 흐름 확인
- 메뉴별 작동 여부 확인
- 외부 자료 연동 확인
- 카드뉴스와 타임라인 동작 확인
- 원본 백업

**완료 기준:** 기존 기능의 기본 동작을 재현하고 테스트할 수 있다.

## Phase 1 ? 원본 장손이 부분 애니메이션

목표: 움직이는 스티커가 아닌 살아 있는 캐릭터 구현.

- 원본 파츠 분리
- 눈 깜빡임
- 미세한 고개 움직임
- 기본 대기
- Hover 반응
- 클릭 반응
- 원본 그림자 보존

**완료 기준:** 정지 상태에서도 작고 자연스러운 행동이 느껴지며 원본의 귀여움이 유지된다.

## Phase 2 ? 보행 캐릭터 제작

목표: 2.5D 보행 스프라이트 구현.

- 원본 기반 서 있는 자세 제작
- 보행 프레임 6~8개 제작
- 소품 처리 및 전환 연출
- 보행 주기 테스트
- 발과 그림자 동기화
- 시작·종료 자세 연결

**완료 기준:** 캐릭터가 미끄러지거나 다른 캐릭터처럼 보이지 않고 자연스럽게 걷는다.

## Phase 3 ? 스크롤 및 카드 포커스

목표: 카카오 문화 페이지에서 참고한 핵심 인터랙션 구현.

- 안내 카드 배치
- 스크롤 진행률 계산
- 카드별 기준 위치 지정
- 장손이 이동 경로 구현
- 걷기 상태와 스크롤 연결
- 활성 카드 전환
- 역방향 스크롤
- 빠른 스크롤 예외 처리

**완료 기준:** 사용자가 스크롤하면 장손이가 각 카드를 따라 이동하고 현재 카드가 자연스럽게 강조된다.

## Phase 4 ? Welcome 및 전체 소개 페이지

목표: 완성도 높은 브랜드 경험 구현.

- 원형 배경 없는 Welcome 화면
- 큰 타이포그래피
- 캐릭터 첫인사
- 섹션 전환
- 사건 입력 안내
- 분석 결과 시연
- 마지막 CTA

**완료 기준:** 장손이가 주인공인 하나의 연결된 웹 경험이 완성된다.

## Phase 5 ? 기존 기능과 통합

목표: 소개 페이지와 실제 업무 애플리케이션 연결.

- 기존 사건 입력 폼 연결
- 기존 메뉴 연결
- 색상 및 타이포그래피 통일
- 기존 검색 로직 회귀 테스트
- 모바일 대응
- 로딩 최적화

**완료 기준:** 새 디자인과 기존 업무 기능이 모두 정상 동작한다.

## Phase 6 ? 선택적 고도화

Phase 1~5 결과를 확인한 후 결정한다.

- 생성형 AI 영상으로 고개 회전 추가
- 고급 감정 표현
- 추가 걷기 방향
- 복잡한 소품 동작
- 더 정교한 그림자
- 장손이 전용 마이크로 인터랙션
- 캐릭터 안내 도우미 기능 확장

# 17. 핵심 테스트 시나리오

## 테스트 1. 첫 방문

사용자가 웹사이트에 접속한다.

장손이가 기존 외형으로 등장한다.

화면에는 큰 환영 문구가 표시된다.

장손이는 조용히 있다가 자연스럽게 눈을 깜빡인다.

## 테스트 2. Hover

사용자가 장손이에 마우스를 올린다.

장손이는 약간 늦게 반응한다.

작은 눈 깜빡임 또는 고개 움직임이 나타난다.

마우스를 움직여도 캐릭터가 포인터를 쫓아다니지 않는다.

## 테스트 3. 스크롤

사용자가 아래로 스크롤한다.

장손이가 걷기 시작한다.

가까워진 카드가 활성화된다.

다음 카드로 이동하면 이전 카드의 강조가 해제된다.

사용자가 멈추면 장손이도 느릿하게 멈춘다.

## 테스트 4. 역방향 스크롤

사용자가 위로 스크롤한다.

장손이가 이전 카드로 돌아간다.

카드 포커스도 이전 항목으로 전환된다.

## 테스트 5. 사건 분석 시작

사용자가 시작 버튼을 누른다.

기존 사건 입력 폼으로 이동한다.

사건을 입력하고 검색을 시작한다.

기존 기능이 정상적으로 작동한다.

## 테스트 6. 모바일

모바일 브라우저에서 스크롤한다.

캐릭터가 내용을 가리지 않는다.

카드가 정상적으로 활성화된다.

입력 폼 사용에 문제가 없다.

# 20. 최종 완료 기준

프로젝트는 아래 조건을 충족해야 한다.

1. 첫 화면에서 원본 장손이를 즉시 알아볼 수 있다.
2. 장손이는 귀엽고 느릿하며 자연스러운 캐릭터성을 유지한다.
3. 단순한 PNG 바운스나 포인터 추적처럼 보이지 않는다.
4. 스크롤하면 장손이가 실제로 걷는 느낌이 난다.
5. 장손이의 이동에 따라 콘텐츠 카드의 포커스가 바뀐다.
6. 사용자가 스크롤을 멈추면 캐릭터도 자연스럽게 정지한다.
7. 발동작과 그림자가 부자연스럽게 분리되지 않는다.
8. 전체 페이지는 밝고 깔끔하며 충분한 여백을 갖는다.
9. 기존 일곱 가지 업무 기능이 그대로 작동한다.
10. 모바일과 모션 감소 환경에서도 콘텐츠와 기능을 정상 이용할 수 있다.

## 최종 비전

**“장손이는 복잡한 손해사정 정보를 안내하는 작은 AI 파트너다. 행동은 조금 멍하고 느릿하지만, 사용자가 스크롤을 내리면 부지런히 걸어가 다음 정보를 소개한다. 사용자는 장손이와 함께 하나씩 기능을 살펴보며, 어렵게 느껴질 수 있는 보험·법률·의학 정보를 조금 더 친근하게 접하게 된다.”**

이것이 장손이 2.0의 기준 경험이다.
